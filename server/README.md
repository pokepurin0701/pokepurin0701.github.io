# 全員参加の応援集計・端末間の引き継ぎ

GitHub Pages は静的ホスティングなので、サーバー側の集計処理は実行できません。フロントエンドは最初から端末内保存で動きます。全員参加の数値は、サーバーを設定するまで未接続と表示し、仮の人数や合計を表示しません。

## Cloudflare Workers + D1 の設定

Cloudflare アカウントで Wrangler を認証した環境で、次を実行します。アカウント作成・認証は所有者が行ってください。

```sh
cd server
npx wrangler d1 create poke-play
```

表示された database_id を `wrangler.jsonc` に記入します。公開先がカスタムドメインなら `SITE_ORIGIN` もその正確なオリジンに変更します。

```sh
npx wrangler d1 execute poke-play --remote --file=0001_initial.sql
npx wrangler deploy
```

表示された Worker の HTTPS URL を `assets/poke-config.js` の `window.POKE_API_URL` に設定してコミットします。DBのIDは秘密鍵ではありません。トークンや Cloudflare の API キーはリポジトリに保存しないでください。

## 挙動

- 訪問日はサーバーの日本時間で1日1回。クライアント指定の日時・回数は受け付けません。
- 全体への応援加算は、各引き継ぎコードにつき1日10回まで。
- 進捗更新はD1のバージョン条件付きUPDATEで競合を検出し、複数タブの二重加算を防ぎます。
- 全員の合計は各参加者の累計貢献をSUMして求めます。
- クライアント生成の256bit引き継ぎコードをBearer認証に利用し、DBにはコードのSHA-256ハッシュだけを保存します。
- 引き継ぎコードを知る人はその進捗を操作できます。アカウントログインや本人確認ではありません。
- 匿名参加なので、ブラウザデータを消してコードを作り直す参加者の重複を防ぐものではありません。高い不正耐性が必要なら認証・レート制限を別途導入してください。
- 端末内の進捗ファイルはサーバーに取り込みません。回数の偽装を防ぐため、サーバー接続後は新しい進捗として始まります。既存の端末内進捗は事前に書き出して保管してください。
- 深夜の秘密は日本時間0〜4時。深夜に来なくても週1回、夢の売店で同じ記念品を取得できます。

サーバーはここでは未デプロイです。CloudflareアカウントとDBの設定後、実際の公開URLでCORS・端末間引き継ぎ・全員集計を確認してください。
