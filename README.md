# ぽけぷりんの公式サイト

トップページは提供された「ぽけの冷蔵庫」を使用しています。埋め込み画像は内容を変えず assets/fridge/ に分離しています。

右下の「ぽけの遊び場へ」から、日替わりコンテンツ、訪問日数による変化、隠し実績などを遊べます。直接の入口は play.html です。

個人の進捗はブラウザ内に保存します。全員の応援集計はサーバーへ接続済みです。遊び場の企画欄から参加できます。[集計ページ](https://app-zlmhhw.v2.appdeploy.ai/) / [実装と保存方法](server/README.md)

## 手紙と、つながる事件

ログイン10回で開く「今日の出来事」と「ぽけからの手紙」から始まります。相談への3つの返事は2日後以降の事件と鍵につながり、30日以上の訪問で届くサイト内の荷物をその鍵で開けます。既存の訪問日数も初回に引き継ぎます。手紙への返信内容によって、2〜4日後に届く返事が変わります。日付・深夜の判定は日本時間です。

リスナーごとの乱数シードで、同じ日に届く手紙や起きる事件が変わります。何もない日もあります。乗っ取り、謝罪の角度、記念日、任命状、深夜のメッセージに対応し、過去の出来事と鍵は既存のアルバム・たからもののタブで振り返れます。Xへの共有は利用者がボタンを押したときだけ開きます。

手紙と事件は `poke-connected-story-v1` として端末内に保存し、返事の本文は外部へ送りません。既存の遊び場の保存領域・集計サーバーとは独立しています。「手紙と事件の記録について・保存」から専用のバックアップを利用できます。制作者向けの `play.html?preview=1` にだけ、本番記録を変更しない回数プレビューと「未来をのぞく」を表示します。通常画面からは将来の部屋を先取りできません（会員認証やアクセス制限ではなく、ブラウザ内の演出です）。従来の遊び・応援企画は折りたたみの中で利用できます。トップページの冷蔵庫と画像は変更していません。

## ログイン回数と訪問日の成長

会員登録は不要です。「ログイン」はこのブラウザのタブでの入場セッションを指します。同じタブでの再読み込みや冷蔵庫・遊び場のページ往復では増えません。別のタブで開くか、30分以上間をあけて戻ると新しいセッションとして数えます。同じ日の再訪も回数に含まれます。訪問日数は日本時間で1日1回だけ増えます。初回の移行では、過去の訪問日数を確認できる最低ログイン回数として引き継ぎます。

- ログイン1〜9回：小さな遊び場、ぽけを褒める、日ごとのプリンスタンプ。
- 10回：手紙への返信・相談・アルバム・たからもの。
- 30回：運営室、業務、機嫌設定、記念品。謎の荷物は別に累計30訪問日とあの日の鍵が必要です。
- 50回：全員の応援企画、夜食の部屋。
- 75回：看板とお部屋をぽけが改装。
- 100回：秘密の休憩室と表彰式。
- 150回：おへやの色を選ぶ模様替え。
- 200回：実家のお茶会（1日1回）。
- 250回：プリン研究所（1日1回の研究ノート）。
- 300回：終身名誉係の表彰状。以後も50回ごとに感謝状。

回数で開く機能と、日付・時間で出る手紙の返事や事件は独立しています。ログインを繰り返しても手紙の待ち時間・訪問スタンプ・30訪問日の荷物は早送りされません。会員登録なしのため進捗は端末内の記録です。ブラウザのデータを消すと失われるため、進捗と物語それぞれの書き出しを利用してください。

トップページには一般公開の遊び場紹介、canonical・OGP・JSON-LDを追加し、`sitemap.xml` と `robots.txt` を配置しています。検索エンジンへの登録・順位は保証しません。Search Consoleの所有権確認やサイトマップ送信は自動では行っていません。

## 12月のお菓子ツリー

毎年12月1日〜31日（日本時間）、トップページと遊び場に渦巻きの緑のクリーム・チョコの土台・金色の星のカップケーキツリーが現れます。みんなで同じツリーを飾り、ニックネームと絵文字をサーバーに保存します。絵文字を押すと、誰がいつ飾ったかが表示されます。一覧にも全員のニックネームが表示されます。表示名は本人認証ではありません。

ニックネーム（1〜20文字）と絵文字を1個選び、匿名の保存コードごとに日本時間で1日1個デコレーションできます。サーバー側で日付と重複を検証します。通信失敗後も同じ送信を再試行でき、二重には登録されません。ツリーには新しい31個を表示し、履歴は100件ずつ追加取得できます。翌年は新しいツリーになります。ブラウザのデータを消しても公開済みの飾りは消えませんが、同じ参加者としての記録は失われます。

`assets/christmas.mjs` が表示、`assets/christmas-client.mjs` と AppDeploy の `src/tree-bridge.ts` が厳密なオリジン検証付きの通信、`backend/index.ts` が共有DBへの保存を担当します。既存の応援集計と同じ保存コードを再利用し、公開データにコードや識別ハッシュを含めません。従来のブラウザ内だけの匿名の飾りは、公開ツリーへ自動送信しません。

本番で共有するには、GitHub Pages側の変更に加えて、既存のAppDeployアプリ `app-zlmhhw` に更新したバックエンドとフロントエンドを再デプロイする必要があります。古い公開先や接続できない環境ではエラーを表示し、ブラウザ内の保存を共有成功として扱いません。詳しくは `server/README.md` を参照してください。

### おためし専用ページ

`christmas-test.html` で12月の表示と飾りつけをいつでも試せます。「テストの参加者」で2人分の操作を切り替え、「翌日に進む」で日次制限の解除を試せます。このページは本番APIに接続せず、このブラウザ内だけのテスト記録を使います。本番用の保存コード・ニックネーム・未確認送信を読み書きしません。「テストをリセット」はテスト専用の記録だけを消します。検索対象外のページで、通常サイトの季節表示や日付は変えません。
