# ぽけぷりんの公式サイト

トップページは提供された「ぽけの冷蔵庫」を使用しています。埋め込み画像は内容を変えず assets/fridge/ に分離しています。

右下の「ぽけの遊び場へ」から、日替わりコンテンツ、訪問日数による変化、隠し実績などを遊べます。直接の入口は play.html です。

個人の進捗はブラウザ内に保存します。全員の応援集計はサーバーへ接続済みです。遊び場の企画欄から参加できます。[集計ページ](https://app-zlmhhw.v2.appdeploy.ai/) / [実装と保存方法](server/README.md)

## 手紙と、つながる事件

累計訪問10日で開く「今日の出来事」と「ぽけからの手紙」から始まります。相談への3つの返事は2日後以降の事件と鍵につながり、30日以上の訪問で届くサイト内の荷物をその鍵で開けます。既存の訪問日数も初回に引き継ぎます。手紙への返信内容によって、2〜4日後に届く返事が変わります。日付・深夜の判定は日本時間です。

リスナーごとの乱数シードで、同じ日に届く手紙や起きる事件が変わります。何もない日もあります。乗っ取り、謝罪の角度、記念日、任命状、深夜のメッセージに対応し、過去の出来事と鍵は既存のアルバム・たからもののタブで振り返れます。Xへの共有は利用者がボタンを押したときだけ開きます。

手紙と事件は `poke-connected-story-v1` として端末内に保存し、返事の本文は外部へ送りません。既存の遊び場の保存領域・集計サーバーとは独立しています。「手紙と事件の記録について・保存」から専用のバックアップを利用できます。制作者向けの `play.html?preview=1` にだけ、本番記録を変更しない回数プレビューと「未来をのぞく」を表示します。通常画面からは将来の部屋を先取りできません（会員認証やアクセス制限ではなく、ブラウザ内の演出です）。従来の遊び・応援企画は折りたたみの中で利用できます。トップページの冷蔵庫と画像は変更していません。

## お菓子の国の身分証（ROYAL PASS）

ログイン回数だけで身分が昇格します。旅人・国民・菓子職人・騎士・貴族・王族を経て、最終目標は50,000回の「お菓子の国の伝説」です。次の称号と必要な残り回数を表示し、昇格時には身分証の色・紋章・ぽけの標準語のセリフが変わります。称号ごとに紙吹雪・星・花びら・王冠などの演出を身分証内で再生し、画面を塞ぐ自動モーダルは表示しません。動きを減らす設定では静かなお知らせに切り替えます。初回に古い記録を読み込んだとき、再読み込み、バックアップ読み込みでは過去の昇格を連続再生しません。

会員登録は不要です。「ログイン」は従来と同じタブ内の入場セッションを指します。同じタブの再読み込みや冷蔵庫・遊び場の往復では増えず、別のタブや30分以上あけた再訪は新しいセッションとして数えます。既存の `poke-play-v1`、ログイン回数、訪問日数、セッションの保存仕様は維持しています。

### 施設と物語は訪問日数で解放

施設はログイン回数や身分では制限せず、日本時間で1日1回記録する累計訪問日数で解放します。

- 訪問1〜9日：小さなお菓子の国、ぽけを褒める、日ごとのプリンスタンプ。
- 10日：手紙・相談・アルバム・たからもの。
- 30日：王城の広間、王城のお手伝い、機嫌設定、訪問記念品。物語の荷物にはあの日の鍵も必要です。
- 50日：全員の応援企画、夜食の部屋。
- 75日：看板とお部屋をぽけが改装。
- 100日：秘密の休憩室と訪問記念。
- 150日：おへやの色を選ぶ模様替え。
- 200日：実家のお茶会（1日1回）。
- 250日：プリン研究所（1日1回の研究ノート）。
- 300日：お菓子の国の記念日。以後も50訪問日ごとに感謝状。

高い身分でも訪問1日なら施設は増えず、訪問日数が多ければ旅人でも施設を利用できます。同じ施設に両方の解放条件を設定していません。手紙の返事の待ち時間・深夜の演出・訪問スタンプも実際の日本時間で進みます。既存の施設開放履歴や称号・記念品は消しません。旧「アルバイト」「係長」などは保存値を保ち、画面上の読み替えだけを行います。お気に入りの実績の名札と、ログイン回数で決まる身分証の称号は別です。

身分の一覧は `assets/poke-royal.mjs` に定義しています。記録は従来と同様ブラウザ内に保存し、進捗と物語のバックアップ・読み戻しに対応します。制作者向けの `play.html?preview=1` ではログイン回数と訪問日数を別々にプレビューできます。昇格演出を試しても本来の進捗は変わりません。

Playwrightの場所が異なるときは `PLAYWRIGHT_MODULE`、Chromiumの実行ファイルが異なるときは `CHROMIUM_PATH` を指定できます。スクリーンショットの保存先は `ROYAL_ARTIFACT_DIR` で指定します。未指定なら作業ディレクトリの `work/royal-browser` に保存します。ブラウザテストは初回表示・全称号・独立した施設解放・昇格・旧データ・手紙・バックアップ・12月表示・スマートフォンを確認します。

トップページの一般公開紹介、canonical・OGP・JSON-LD、`sitemap.xml`、`robots.txt` は維持しています。検索順位やSearch Consoleの操作はこの変更の対象外です。

## 12月のお菓子ツリー

毎年12月1日〜26日（日本時間）、公式サイトと遊び場のトップに渦巻きの緑のクリーム・チョコの土台・金色の星のカップケーキツリーが現れます。みんなで同じツリーを飾り、ニックネームと絵文字をサーバーに保存します。絵文字を押すと、誰がいつ飾ったかが表示されます。一覧にも全員のニックネームが表示されます。表示名は本人認証ではありません。

ニックネーム（1〜20文字）と絵文字を1個選び、ツリーの好きな場所をタップして仮置きし、「ここに飾る」で決定します。決定前なら別の場所を選んで動かせます。匿名の保存コードごとに日本時間で1日1個デコレーションできます。飾りの周囲に選択用の丸は表示しません。位置はツリー内の比率で保存し、スマートフォンでも同じ場所に表示します。位置のない従来の飾りは自動配置を引き継ぎます。矢印キーでの位置調整とEnterでの決定にも対応します。サーバー側で日付と重複を検証します。通信失敗後も同じ送信を再試行でき、二重には登録されません。ツリーには新しい31個を表示し、履歴は100件ずつ追加取得できます。翌年は新しいツリーになります。ブラウザのデータを消しても公開済みの飾りは消えませんが、同じ参加者としての記録は失われます。

`assets/christmas.mjs` が表示、`assets/christmas-client.mjs` と AppDeploy の `src/tree-bridge.ts` が厳密なオリジン検証付きの通信、`backend/index.ts` が共有DBへの保存を担当します。既存の応援集計と同じ保存コードを再利用し、公開データにコードや識別ハッシュを含めません。従来のブラウザ内だけの匿名の飾りは、公開ツリーへ自動送信しません。

本番で共有するには、GitHub Pages側の変更に加えて、既存のAppDeployアプリ `app-zlmhhw` に更新したバックエンドとフロントエンドを再デプロイする必要があります。古い公開先や接続できない環境ではエラーを表示し、ブラウザ内の保存を共有成功として扱いません。詳しくは `server/README.md` を参照してください。

遊び場ではページ見出しのすぐ下に、日本時間の12月1日午前0時から12月26日まで表示します。表示期間外はツリーもおためしページへの案内も表示しません。おためし専用ページは直接URLから利用できます。

### おためし専用ページ

`christmas-test.html` で12月の表示と飾りつけをいつでも試せます。「テストの参加者」で2人分の操作を切り替え、「翌日に進む」で日次制限の解除を試せます。このページは本番APIに接続せず、このブラウザ内だけのテスト記録を使います。本番用の保存コード・ニックネーム・未確認送信を読み書きしません。「テストをリセット」はテスト専用の記録だけを消します。検索対象外のページで、通常サイトの季節表示や日付は変えません。
